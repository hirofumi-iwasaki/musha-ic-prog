# 読み取り専用バイナリー表示とICテストの追加設計

2026-09-16 / 設計確定、実装・実機確認は未実施。
本書はDESIGN.mdの表示機能とICテスト境界の詳細仕様とする。

## 1. 追加範囲

| 機能 | 0.1.0での位置づけ |
| --- | --- |
| 読み取り専用バイナリービューアー | 必須 |
| ロジックICテスト | 条件付き追加候補。TL866CSと完全型番・テストベクトルの実機検証合格で有効化 |
| SRAMテスト | minipro forkで基本試験を実装。TL866CS実機は電源保持・ピン操作の検証後に有効化 |

## 2. バイナリービューアー

### 表示とデータ

入力BINとIC読出しの不変スナップショットを表示する。左をInput BIN、右をIC Readoutとし、
片方のみでも閲覧可能。読戻し結果にはReadout / Post-write verificationの由来と日時、IC型番を表示する。
常時ICを読んでいるライブ表示ではない。再読出し失敗時は前回成功結果を残し、古い結果であることを明示する。
書込み入力・IC読出し・照合結果を同じデータとして上書きしない。

- 行頭アドレスは16進数、データは1 byteあたり2桁のHEX、右端にASCIIを表示。
- ASCIIの印字可能範囲は0x20〜0x7E、それ以外は`.`。データ不存在は`--`で0x00と区別する。
- 1行16 bytesを既定とし、8 / 16 bytesを切替可能。
- クリックしたbyteのアドレス、HEX、符号なし10進数、8桁2進数（bit7→bit0）、ASCIIを詳細欄に表示。
  例: `0x41 / 65 / 01000001 / A`。不存在・未取得byteは値を捏造せず「—」とする。
- ファイル名・由来、容量bytes、SHA-1、Read only表示を各ペインに置く。
- 行番号や文字列を全ファイル分生成せず、表示範囲をページ単位で取得する。

### 操作

縦スクロールは両ペインの同じ絶対アドレスへ同期する。横スクロールと狭いウィンドウに対応する。
矢印キーでbyte選択、Page Up / Down、Home / Endで移動し、Command+Gで16進アドレスへ移動する。
ジャンプは選択ペインのデータ範囲を検証し、範囲外・空データで不正位置を選ばない。
次／前の差分へ移動できる。比較中・異なる世代の結果では差分移動を無効にする。

Edit切替、文字入力による変更、貼付け、削除、上書き保存は提供しない。
選択byteの値・アドレスのコピーを提供し、クリップボードへの書込みは明示操作時のみ行う。
ReadoutのSave Asは読み出した全バイナリーを保存する操作であり、表示部の編集機能ではない。
範囲選択、多byteの解釈（endianness）、検索は後続機能とする。

### 差分

共通するアドレスの値不一致と、片方にしかないbyteを別の色と凡例で表示する。
一致・未比較・比較中・失敗を区別し、未比較を一致色だけで表さない。
比較は不変snapshot同士のbyte比較。ファイル長が異なる場合も閲覧比較はできるが、
ICへの書込み・ハードウェアVerifyは従来どおり容量一致を必須にする。
すなわち、任意のBINを閲覧することと、書込み用入力として受理することを分離する。
差分件数と最初の不一致を集計し、全差分を無制限に保持しない。

### musha-bin-editorからの参照

参照revision: `f00daaeb0f51d708cbbd83588207071966509547`
参照実装: `lib/presentation/hex_pane.dart`、README、4層構成。
`HexMetrics`の文字実測、`HexLayout`のHEX/ASCII配置、表示行のみの描画、
横スクロールと縦スクロールの調整、上限付き文字描画キャッシュを参考にする。
編集状態や編集コールバックまで持ち込まず、読み取り専用の`BinaryViewer`として必要な部分を構成する。
姉妹アプリのソースを移植する場合はGPL表示と参照revisionを残す。
表示領域は`BinaryViewSource.readRange`相当の抽象を参照し、USBやminiproを呼ばない。
CPU負荷のある比較・ハッシュはisolate、ページ取得は非同期、更新はsnapshot世代で検証する。
初期値は64 KiBページ、8ページまでのキャッシュ、文字描画キャッシュ2048件を上限とし、実測で調整する。
拡大文字、ダークモード、VoiceOverで選択byteのアドレスと値を理解できるようにする。

## 3. ロジックIC・SRAMの調査結果

minipro調査revision: `cae74c0607077d6260b24995f5e4c0d0b66a6a2e`。
採用版の決定や実機動作確認ではない。

- `man/minipro.1`の`-T / --logic_test`はRAM / Logic IC testを記載している。
- `src/minipro.c`ではTL866AとTL866CSが`tl866a_logic_ic_test`を共有する。
- `src/tl866a.c`の同関数はテストベクトルと期待ピン状態を比較する処理を持つ。
- 0.7の公式リリースノートもTL866CS/Aのロジックテスト追加を明記している。
- 調査版の`tl866a_logic_ic_test`には他機種のような`MP_SRAM`から専用RAMテストへの分岐がない。
  `tl866iiplus.c`、`t48.c`等には`minipro_test_ram_generic`への分岐が存在する。
  そのためCLIの共通説明やDBにSRAM型番があることだけでTL866CSのSRAMテストを有効にしない。
- 共通RAM処理はデータバス、アドレス断線／短絡、セル、increment試験のエラーを扱う。
  調査版では正常ステータスの判定が広く、終了処理の戻り値を確認せず成功を返す箇所もある。
  今後採用する場合、応答長・正常ステータス・終了成功を確認する契約と必要な修正を先に検証する。

## 4. テスト用の設計

ROMのprogram / verifyとは別に`logicTest`、`sramTest`を操作種別へ追加する。
既存OperationCoordinatorの排他・接続世代・中断・復旧管理を共用し、BIN入力を必須にしない。
`DeviceProfile`をEPROM / Logic / SRAMの種別付きモデルに拡張する。
共通項目は完全型番、パッケージ、電圧、配置、backend mapping、検証記録。
容量とmemory領域はメモリー機種だけ、ベクトルはLogicだけに持たせ、ダミー容量を入れない。

`TestProfile`はprofileId、版・hash、対象完全型番、backend/firmware条件、電圧・配置、
試験種類、ベクトルまたはアルゴリズムID、破壊性、時間上限、確認済みの中断方針、根拠とライセンスを持つ。
能力は機種×firmware×IC×テストprofileの積で判定し、単にbackend全体のtrue/falseにしない。
未知の組合せは無効。ユーザー作成ベクトルや任意電圧指定は初期対象外。

`TestResult`は`passed / failed / inconclusive / cancelled`を区別し、
operationId、対象・profile版、実施範囲、経過時間、backend診断、終了・電源解放状態を含む。
通信エラーや判別不能な結果はIC不良と断定せずinconclusiveとする。
「この試験を通過」と表示し、すべての機能・速度・電気特性を保証する「良品認定」にしない。

### ロジックIC

確認済みの組合せ回路を初回候補とし、74xx等の系列名だけでLS / HC / HCT等を同一扱いしない。
入力ベクトルを印加し期待出力と比較。試験番号、パッケージのピン番号、期待状態、観測値を表で示す。
観測値がCLIから得られない場合は未取得と表示し、期待値の反転から推測して埋めない。
クロック・順序回路・三態出力等は試験ベクトルが検証されるまで対象外とする。
上流のZ判定が電気的な高インピーダンスの完全測定を意味するとは扱わない。
最初は登録済みベクトルによる機能試験に限定し、速度・負荷・漏れ電流は保証対象外。

### SRAM

SRAMテストは記憶内容を書き換える破壊的試験。起動前に明示確認し、元内容の保存・復元を約束しない。
基板から取り外した対応ICをZIFで試験し、インサーキットやバッテリーバックアップ用途を初期対象にしない。
既存のRAMテストを利用できる機種では、その試験内容とエラー形式を実機検証して採用する。
TL866CSに対して汎用ROMのread / writeをそのまま代用しない。
専用バックエンドを追加する場合は0x00 / 0xFF、checkerboard、walking-bit、アドレス試験、
March試験等を候補とし、実装・検証したものだけ表示する。これらを上流の実装済み機能と称さない。
エラーは種類と有効なアドレス／ビットを分け、アドレス線番号をメモリーアドレスとして表示しない。
8 bit以外のバス幅もprofileで表現し、不明なexpected/actual値や全メモリーダンプを結果から捏造しない。

### UIと終了

IC種別に応じてMemory / IC Test表示を切り替える。テスト画面にTestボタン、型番・配置、試験説明、結果表を置く。
LogicではProgramやBlank Checkを出さない。SRAMは内容消失の説明を伴う。
テスト中も接続1台の排他と終了保留を適用し、切断・過電流等では次の試験を自動開始しない。
結果レポートをJSONまたはテキストで明示的に保存できる。レポートはBinaryImageとは別のデータである。
ロジック試験データのMIT等の表示は同梱ライセンス調査に従い、採用するベクトルの出典まで記録する。

## 5. 追加検証条件

ビューアー: 00 / FF / 41、ASCII境界、先頭・末尾、0 byte、部分最終行、8/16切替、
不等長比較、拡大文字、同期スクロール、範囲外ジャンプ、古いsnapshot、未比較状態を検証。
入力・貼付け・削除操作でデータが変わらず、元ファイルhashが変化しないことを確認する。

Logic: 既知の正常ICと検証済みベクトルで期待結果を確認し、mock/fixtureでピン不一致、
未知出力、通信異常、終了失敗を再現する。CLIのANSI色コードを除去しても結果が変わらないことを検証する。
SRAM: TL866CSへの実行拒否を先に検証。対応機種を追加する時点で正常・不一致、破壊的試験確認、
アドレス線番号とメモリーアドレスの区別、未知ステータス拒否、終了処理失敗を検証する。
実機結果はOS、機種、firmware、完全型番、電圧、profile/hash、採用revisionとともに残す。
